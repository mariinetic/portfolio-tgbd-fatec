Como o akpedia-ml funciona, de ponta a ponta

Serviço Python 3.12 + FastAPI que lê documentos, gera embeddings, sugere título e categoria no upload e indexa os documentos aprovados para a busca. Cada fluxograma abaixo mostra o caminho real do código e em qual arquivo cada passo mora.

Visão geral da arquitetura

Dois processos saem da mesma imagem Docker: a API (uvicorn app.main:app) e o worker (python -m app.worker). Os dois carregam o mesmo modelo de embedding. O compose também sobe o Ollama, num container sem porta exposta, que a rota /chat/answer usa para escrever as respostas do chat.

A jornada de um documento

A ordem em que as partes do ML entram em cena, do upload até a busca.

POST /api/v1/documents/analyze

Sugestões no formulário de upload

Poupa digitação: devolve título, descrição e categoria provável antes de o documento ser aprovado.

Ordem do título

1) linha de assunto acima de AGENCY: (Federal Register); 2) /Info /Title sem prefixos tipo Microsoft Word -; 3) texto de maior fonte se maior que o corpo; 4) nome do arquivo.

Descrição

Parágrafo SUMMARY: se existir; senão o primeiro parágrafo corrido das 3 primeiras páginas com ≥ 40 caracteres, cortado em 500 sem partir palavra.

Limpeza do layout

Remove cabeçalho e rodapé que se repetem entre páginas e números soltos nas faixas de 8% do topo e da base. Colunas são lidas uma depois da outra.

Categoria

Média dos vetores de até 20 chunks, cosseno contra cada centróide, softmax com T = 0.05. confidence é a probabilidade da vencedora; scores soma 1.

worker.py · e também POST /api/v1/documents/process

Indexação de documentos aprovados

Depois da aprovação o server coloca o documentId no stream Redis. O worker roda o mesmo pipeline do /process (extrair, dividir, embedar) e devolve o resultado no mesmo formato JSON.

/process (síncrono)

Mesmos passos 3 a 5, mas o arquivo chega no upload e a resposta volta na hora: filename, model {name, dimensions: 384, normalized}, chunk_count e chunks[] com index, text, embedding.

Chunks

Frases inteiras, ≤ 1000 caracteres, overlap de até 200 alinhado por frase. Quebra de linha simples vira espaço; só frase gigante é cortada por palavra.

Mensagens pendentes

No start, o worker retoma primeiro as próprias mensagens que o server ainda não confirmou (XPENDING + XCLAIM) e só depois lê as novas.

Consumer group

O group ml-workers começa do início do stream, então documentos aprovados antes do primeiro worker subir também são indexados. O stop_grace_period de 2 min deixa o documento atual terminar.

POST /api/v1/embeddings/query

Busca semântica

O ML só transforma o texto digitado em vetor. A comparação com os chunks acontece no PostgreSQL do server.

POST /api/v1/chat/answer

Resposta do chat

O server manda a pergunta e os trechos que já filtrou por permissão. O ML não toca no banco: só escreve uma resposta curta em português, citando os trechos de onde ela saiu.

Prompt

Português, no máximo três frases, cada afirmação com o número do trecho. Os trechos são dados, não instruções. Fica em chat/prompt.py.

Não encontrado

Se os trechos não respondem, o modelo escreve SEM_RESPOSTA e a rota devolve found: false, em vez de inventar.

Janela do modelo

O Ollama cortaria o começo de um prompt longo, onde ficam as regras. Por isso os trechos menos relevantes saem antes, aqui.

Falhas

Modelo fora do ar ou lento: 503 llm_unavailable, com os detalhes só no log.

scripts/build_centroids.py

Geração dos centróides de categoria

Passo offline que ensina ao /analyze como cada categoria "soa". Sem o arquivo, a API continua respondendo, só que com category: null.

Onde está cada coisa

Caminhos relativos a src/app/, exceto no último grupo.

Entrada e configuração

src/app/main.py

Cria o app FastAPI, registra as routers de documentos, embeddings e chat, expõe /health e carrega os centróides no startup.

src/app/config.py

Todas as variáveis de ambiente com default. Lidas uma vez no import; valor inválido derruba no start.

src/app/embeddings.py

Contrato Embedder e SentenceTransformerEmbedder (e5, prefixos passage:/query:). get_embedder() é singleton.

src/app/worker.py

Worker de indexação: IndexingWorker (Redis), ServerClient (rotas /internal), logs JSON e retomada de mensagens pendentes.

api/ · rotas HTTP

api/documents.py

/process e /analyze, modelos de resposta, limite de upload e build_process_response() (reusado pelo worker).

api/embeddings.py

/embeddings/query: vetor de um texto de busca.

api/chat.py

/chat/answer: resposta do chat a partir dos trechos.

documents/ · leitura do arquivo

documents/service.py

extract_text(): ponto de entrada; escolhe o extrator no default_registry.

documents/registry.py

Mapeia extensão e media type para extrator. Formato novo = registrar aqui.

documents/base.py

Contrato DocumentTextExtractor e normalize_text_parts().

documents/pdf.py

PdfTextExtractor com pypdf (só a camada de texto, sem OCR).

documents/chunking.py

split_text(): frases inteiras, chunk ≤ 1000 chars, overlap ≤ 200 alinhado por frase.

documents/inspection.py

inspect_pdf() com PyMuPDF: metadados, páginas, fontes, colunas, cabeçalho/rodapé, padrão Federal Register.

analysis/ · sugestões do upload

analysis/suggestions.py

Regras de título (Federal Register → /Title → maior fonte → nome do arquivo) e descrição (SUMMARY → primeiro parágrafo corrido).

analysis/categories.py

Centróides: amostragem de chunks, média dos vetores, cosseno, softmax com temperatura, leitura/gravação do .npz.

chat/ · resposta do chat

chat/llm.py

Contrato LLMClient, OllamaClient (API nativa /api/chat, com num_ctx e num_predict) e FakeLLMClient para testes.

chat/prompt.py

Prompt com os trechos numerados, leitura das citações e corte da resposta.

chat/answer.py

answer_question(): junta prompt, modelo e fontes citadas.

Fora de src/

scripts/build_centroids.py

CLI que gera centroids.npz a partir de documentos já classificados.

tests/

Um arquivo por módulo; fixtures/real/ tem PDFs reais (Federal Register, FAA) para regressão das sugestões.

docker-compose.yml

Serviços app (API), worker e ollama. O Redis vem do compose do server, na rede akpedia-net.

.github/workflows/ci.yml

Pipeline de CI do repositório.
